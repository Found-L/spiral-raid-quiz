# 国内成绩服务

`server.py` 使用 Python 3.12 标准库和 SQLite；生产服务监听 `127.0.0.1:8791`，由 Nginx 的 `/spiral-raid-quiz/api/` 反向代理。GitHub 和国内网页使用相同的 API、排行榜及数据库；旧 Sites API 转发到同一服务。

`POST /api/history/review` 校验浏览器身份及答卷归属，按该次题库返回已保存的错题、正确答案和解析；旧成绩未保存明细时返回不可查看，不推测所选选项。错题数据不出现在公开榜单。

管理页面及 `/api/admin/` 使用独立的管理员密码和短期登录会话，限国内站同源访问；密码哈希保存在数据目录的 `admin-auth.json`，不放入仓库。接口支持查看汇总、玩家、答卷错题、勋章获得者、互动和举报，并审核、下架或删除评价；不返回身份密钥或哈希。普通勋章的时间按现存答卷首次达到条件的上传时间计算，纪录类勋章沿用历史推算和留档。原始所选选项从未上传，旧答卷缺失错题标记时不能恢复。页面可修改管理员密码，修改后所有管理会话失效。

生产文件位于 `/opt/spiral-raid-quiz/app/`，网页位于 `/opt/spiral-raid-quiz/public/index.html`，数据库位于 `/var/lib/spiral-raid-quiz/quiz.sqlite3`。服务和数据由独立的 `spiral-quiz` 系统账号运行和保护。

`spiral-raid-quiz-backup.timer` 每天创建 SQLite 一致性快照，保留最近 14 份，目录为 `/var/lib/spiral-raid-quiz/backups/`。备份位于同一台服务器，应另行定期复制到其他受保护的位置；身份哈希及答题记录不可公开。手动备份可运行 `systemctl start spiral-raid-quiz-backup.service`。

更新题库时，在项目根目录运行 `python build_questions.py` 和 `python build_page.py`，使网页和 `domestic-backend/questions.json` 版本一致。`banks/` 保留旧题库，服务按提交的版本评分，历史记录保留所有版本。`/api/leaderboard?view=latest` 综合每位玩家的最新已完成题库版本，同版本取最高分；分数相同按用时、上传时间排序。`version` 参数可查询单个题库版本；无参数保持旧客户端的当前版本行为。榜单支持 `page`（从 1 开始）和 `pageSize`（1 至 100），返回总人数、总页数和全局排名；不传分页参数时兼容旧客户端并返回前 100 名。旧记录没有用时，显示为未记录。

`/api/badges` 和 `/api/badges/select` 使用现有浏览器身份校验勋章及展示选择。成绩类勋章由已保存的成绩计算，最多展示 3 枚；未选择时自动展示成绩类勋章，明确保存空列表时不展示。机制趣味勋章依据经评分校验的指定错误选项解锁，只记录对应勋章、不存逐题答案，并由本人选择后才公开展示。服务先前没有保存答案，无法给已上传的旧成绩反推错题勋章；新收到的 v5 至 v10 答卷按各自题库判定。最快勋章按全站所有已计时答卷的最低用时实时计算，并列均获得；无计时的旧成绩不参与。客户端从 v7 起仅记录答题页前台时间，旧时间可能包含离开页面的时间；用时由客户端提交，不提供防作弊保障。选择与错题勋章分别写入独立表，删除个人资料时级联清除，不改写历史成绩。

勋章接口另返回人数统计：普通勋章按留存的不同身份去重；错题勋章少于 3 人时只返回隐藏标记；四个纪录勋章返回当前持有人数及基于现存答卷、当前规则和新增纪录事件合并去重的历史推算人数。旧答卷缺失或删除、补传及客户端完成时间不准确可能影响历史推算；删除资料会清除该身份的纪录事件。统计结果缓存最多 30 秒，上传答卷或删除资料后失效。

排行榜批量返回表情、公开评价数和最高赞评价，点赞相同时按发表时间倒序；无点赞时展示最新评价。`/api/social/view` 供访客读取互动详情，使用现有身份时附带本人状态；`/api/social/reaction`、`comment`、`like`、`delete`、`hide` 和 `report` 均要求身份校验。服务端限制表情种类、一人一条评价及点赞，并限制操作频率；修改评价清空其原有点赞，评论按纯文本展示。浏览器身份不是实名账号，不能保证一人只有一个身份。新增表使用外键级联，删除资料时会清理相关互动。

`POST /api/shares` 通过浏览器身份创建个人勋章、综合排名或趣味榜名次的快照，服务端重新校验获奖与排名；`GET /api/shares/<id>` 公开读取该快照。随机分享编号不包含身份码，同一身份相同内容复用链接。快照反映分享时状态，删除资料时级联删除分享记录；原有下载图片无法远程撤回。

被评价人自行隐藏的评价由本人恢复；管理员下架时保留原有隐藏状态，恢复后不会覆盖被评价人的选择。举报记录保留举报时的内容快照；评价被修改后，审核时不能将旧举报直接作用于新内容。删除评价保留举报快照供审核，涉及的身份被删除时级联清除相关举报。新表随现有 SQLite 一致性备份保存；部署时需要一并安装 `social.py` 和 `badge_metrics.py`，启动会安全创建缺失的表。

`/api/honors` 提供四项全站趣味榜：不限分数的最短用时、累计完成轮数（至少 2 轮）、累计满分次数（至少 1 次）和满分答卷最短用时。统计所有已上传的新旧题库答卷，每人每项取其记录；计时榜排除未记录用时的答卷。首页每项返回前 5 人、全部并列第一的人数和上榜人数；同成绩优先按达到该成绩的时间升序，时间也相同则按榜单编号排序。新答卷使用浏览器记录的完成时间（异常时间回退至上传时间），旧答卷没有完成时间时使用上传时间。`/api/honors?badge=quickest&mode=current&page=1&pageSize=20` 分页提供完整当前榜单；`mode=history` 合并现存答卷推算结果和上线后的纪录留档，并标识是否仍持有；只有留档而无法推算当时成绩时显示记录时间。相同毫秒的答卷作为一批计算，删除的记录无法还原，缺少用时的答卷不参与计时榜。所有并列第一者都获得对应的实时纪录勋章，纪录被超越时失去资格；历史名单不改变勋章或答卷。完成时间与用时由浏览器提交，属于娱乐统计而非防作弊排名。

部署时先备份数据库，将服务、新题库与旧题库归档安装到服务目录并重启 `spiral-raid-quiz.service`，再更新网页和 GitHub Pages。服务启动时会创建独立的用时表，原有成绩表保持不变，备份仍按原方式执行。变更 Nginx 时先执行 `nginx -t`，通过后才 reload，并检查现有网站和 API 的健康状态。原网站的 Nginx 配置含有 `include /etc/nginx/snippets/spiral-raid-quiz.conf;`，重新生成配置时需保留该行。

本地校验：

```sh
python -m unittest discover -s domestic-backend -p 'test_*.py'
```

迁移脚本 `import_snapshot.py` 只接受空数据库，并在同一事务内导入身份、玩家编号、成绩和编号序列；任一校验失败会回滚。不要对已经接收玩家成绩的数据库再次执行导入。
